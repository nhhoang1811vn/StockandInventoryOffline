# Auto-lock After Inactivity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-lock the app after N idle minutes (default 30, user-editable 1–1440) for users who have passcode lock on, using the existing lock screen.

**Architecture:** Pure rules and preferences live in `AppSettings`. An app-level `AppLockService` owns the idle clock, a 10 s periodic check and the "show lock screen" routine extracted from `MainPage`. A `Listener` in `MaterialApp.builder` and a lifecycle observer in `MyAppState` feed it. General Settings gets one always-visible minutes row (no on/off switch).

**Tech Stack:** Flutter, flutter_bloc + freezed + injectable, `flutter_screen_lock`, `BiometricAuthService` (already in repo), `easy_localization`.

**Spec:** [docs/superpowers/specs/2026-11-17-auto-lock-design.md](../specs/2026-11-17-auto-lock-design.md)

**Commits:** commit steps run only if the user has asked for commits; otherwise skip them.

## Global Constraints

- Minutes range 1–1440, default 30. There is **no** on/off switch: auto-lock is always on, but it only has effect when `AppSettings.getEnablePasscode()` is true. Users without passcode never get locked.
- Preference key: `AutoLockMinutes` (only).
- Cold-start lock stays in `MainPage` and its behaviour (passcode + optional fingerprint) is unchanged; auto-lock reuses it.
- Never show two lock screens; never block unlocking; idle time counts while in the background.
- No new dependency. Strings in all 11 files in `assets/translations/`, edited directly. Do not hand-edit `*.freezed.dart`, `*.g.dart`, `lib/di/di.config.dart`; re-run `dart run build_runner build --delete-conflicting-outputs`.
- No business logic in widgets; the minutes row is always visible (no switch, not hidden when passcode is off).

## Review Focus

1. Dialog input empty, non-numeric, decimal, negative, 0 or > 1440 → inline error, OK refused; stored corrupt value → clamped (Task 1 tests, Task 3 manual).
2. Lock screen already open, or user is still on the loading route before `MainPage` starts → no second lock, no lock before `MainPage` (Task 2 tests on the guard; manual).
3. App paused longer than N, then resumed → locked immediately; paused shorter → not locked (Task 1 `shouldLock` tests, Task 2 manual).
4. User turns passcode off while auto-lock is on → never locks (Task 2 `isActive` test).
5. Unlock resets the clock so the app is not re-locked right away; touches on pushed routes/dialogs count as activity (Task 2 manual).

### Task 2: `AppLockService` and app hooks

**Files:**
- Create: `lib/core/services/app_lock_service.dart`
- Modify: `lib/presentation/pages/main/main_page.dart` (`_showLockScreen`, `_unlockWithFingerprint`, `_lockOpen`, ~lines 118–165)

- Test: `test/auto_lock_test.dart` (no new tests beyond Task 1; this task is verified by analyze + manual checks, since it depends on platform lifecycle and `flutter_screen_lock`)

**Interfaces:**
- Consumes: `shouldAutoLock`, `AppSettings.getEnablePasscode/getAutoLockMinutes/getEnableFingerprint/getPasscode`, `BiometricAuthService.authenticate`, translation keys `enter_pin_to_unlock`, `fingerprint_unlock_reason`.
- Produces: `@lazySingleton class AppLockService` with
  - `void start(GlobalKey<NavigatorState> navigatorKey)` — idempotent; records `lastActivity = now`, starts a `Timer.periodic(Duration(seconds: 10))` that calls `_check()`.
  - `void markActivity()` — sets `lastActivity = DateTime.now()` (cheap, called on every pointer event).
  - `void onLifecycleChanged(AppLifecycleState state)` — on `resumed` calls `_check()` immediately.
  - `void showLock()` — the logic moved verbatim from `MainPage._showLockScreen` (passcode `screenLock`, `onOpened`/`customizedButton*` for fingerprint, `_lockOpen` guard), but using `navigatorKey.currentContext`; on unlock/fingerprint success sets `_lockOpen = false` and `lastActivity = now`. No-op if passcode is off or a lock is already open.
  - `_check()` calls `showLock()` when `shouldAutoLock(...)` is true; does nothing before `start()`.
